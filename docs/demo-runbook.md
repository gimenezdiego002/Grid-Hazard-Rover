# Relay: five-minute judge rehearsal

Open the local dashboard at **http://127.0.0.1:8765/**. If it is stopped, run `scripts/start-demo.ps1` from the project folder. Keep the **SIMULATION** banner visible. Say: “Relay coordinates a station, scout and announcer, and spends model calls when evidence changes. Today we are rehearsing the workflow with synthetic water readings.” No hardware is connected, no motion or real announcements occur, and all dashboard provider calls are mocked.

Before the presentation, run `.\.venv\Scripts\python.exe scripts/rehearse-demo.py` once and keep its HTML packet available as an offline fallback. It saves actual results from that mock rehearsal in a new directory; it does not check cloud accounts or connect devices. See [packet contents and checks](rehearsal-packet.md).

1. **Plan and inspect.** Under **Choose the inspection.**, select **Preset water inspection**, keep Station `station-a`, and click **Plan simulated mission** → **Start simulation** → **Simulate next task**. The scout step changes the button to **Analyze synthetic evidence**. Use it to show the suspected-water finding and **Evidence to action** trail. Leave the default allowance at 12 requests, 24,000 tokens and $0.10. A suspected hazard is provisional; completing an observation does not establish safety.

2. **Show the review boundary.** The mission stops at `needs_review`. Click **Simulate operator review**, then **Simulate next task** to finish **Announcement rehearsal**. Open **Inspect mission record**: the workflow can finish while `human_review_performed` remains false and `environment_safety` remains `not_established`. Explain that this button rehearses the review transition; it is not production authorization. No MP3 is generated or played. For directed dispatch, choose **Directed inspection**, set Target area to `loading-bay`, select a Scout, and plan another mission. These are logical assignments, not robot navigation. **Include a second observation** is optional; the default unavailable hexapod is skipped rather than presented as connected.

3. **Demonstrate economy.** Click **Compare policies**. For the existing twelve-sample fixture with one synthetic wet interval, the recorded comparison is **12 versus 1 model requests** and **3,743 versus 312 simulated tokens**, fixed interval versus economy. Show the returned numbers and simulated cost labels; **ACTUAL PAID API COST** for the mock replay is zero. Pitch: “We gate and deduplicate evidence before inference, then make the allowance and decisions visible.” This is one synthetic event, not an accuracy benchmark. Fewer calls and tokens demonstrate less modeled work here; no energy, carbon, battery-life or water savings have been measured.

4. **Show refusal without false reassurance.** Click **Test budget refusal** and show **Human review needed.** This button uses a zero-request allowance for that replay. To demonstrate the mission boundary too, set **Request limit** to `0`, create a new mission and advance to **Analyze synthetic evidence**. Even after **Simulate operator review**, the budget-refused mission remains `needs_review`; it cannot proceed to an announcement. Restore Request limit to `12` afterward.
